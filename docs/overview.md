## 1. ระบบนี้แก้ปัญหาอะไร

บริษัท DTC มีสินค้าด้าน GPS Tracking / กล้องติดรถ / IoT Solution จำนวนมาก แต่ละตัวมีสเปคละเอียดและชื่อรุ่นที่คล้ายกัน (DTRACK, DTRACK-M, DTRACK-O, DTRACK-A, DTRACK-CR …)

**ปัญหาที่เจอหน้างาน:**
- **ทีมขายจำสเปคสินค้าทุกตัวไม่ได้** เวลาลูกค้าถามว่า "รุ่นนี้กับรุ่นนั้นต่างกันยังไง" ต้องเปิดเอกสารทีละไฟล์มาเทียบเอง
- **ลูกค้าเรียกสินค้าด้วยชื่อย่อ/ชื่อรุ่นที่ไม่ตรงกับชื่อในระบบ** หรือพิมพ์ผิด ทำให้ค้นหาไม่เจอ
- ไม่มีที่ใดที่ **เทียบสเปคสินค้าหลายตัวพร้อมกันแบบเคียงข้าง** ได้

**สิ่งที่ระบบนี้ให้:**

| ผู้ใช้ | ได้อะไร |
|---|---|
| **ทีมขาย** | เปิดหน้าเว็บตอบลูกค้าได้ทันที ค้นหาด้วยคำที่ลูกค้าพูด (พิมพ์ผิดก็เจอ) แล้วลากสินค้ามาเทียบสเปคกันได้สูงสุด 4 ตัว |
| **ลูกค้า** | เข้ามาค้นหา/เทียบสินค้าเองได้โดยไม่ต้องรอพนักงาน |
| **แอดมิน** | จัดการข้อมูลสินค้า สเปค หมวดหมู่ โมเดล และเนื้อหาเว็บทั้งหมดผ่านหน้าจอ ไม่ต้องแตะฐานข้อมูล |

## 4. ฐานข้อมูล

**จุดสำคัญที่ควรพูดตอนนำเสนอ:** ระบบนี้ **ไม่ได้ออกแบบตารางขึ้นมาเอง** แต่ใช้ **สำเนาโครงสร้างตารางจริงของ dtcshops.com** (สลับมาใช้เมื่อ 1–2 ก.ย. 2026) — ทำให้สิ่งที่พัฒนาขึ้นสามารถต่อยอดกับระบบจริงของบริษัทได้โดยไม่ต้องแปลงข้อมูลใหม่ ฐานข้อมูลชุดนี้เป็นสำเนาในเครื่อง ไม่ได้เชื่อมต่อกับเว็บจริง

### ตารางที่ระบบใช้งานจริง

| ตาราง | เก็บอะไร | ข้อมูลปัจจุบัน |
|---|---|---|
| `tbl_item` | สินค้า | 81 แถว (ใช้งานอยู่ 43) |
| `tbl_item_type` | หมวดหมู่สินค้า | 6 หมวด |
| `tbl_attribute` | ชื่อหัวข้อสเปค | 98 หัวข้อ |
| `tbl_attribute_value` | ค่าสเปคของแต่ละสินค้า | 565 ค่า |
| `tbl_item_model` | โมเดลย่อยของสินค้า | 21 โมเดล |
| `tbl_item_option` | ตัวเลือกเสริม (เช่น SD Card, เซ็นเซอร์ GPS) | 21 รายการ (เพิ่มอุปกรณ์เสริม GPS 8 รายการ 11 ก.ย. 2026) |
| `tbl_bnn_slide` | แบนเนอร์หน้าแรก | 3 |
| `tbl_shop` | สาขา DTC Shop | 15 |
| `tbl_footer` | เนื้อหา footer | 21 |
| `tbl_logs` | สถิติการเข้าชม | 40,309 |
| `tbl_users` | บัญชีแอดมิน | 2 |

> รวม **11 ตาราง** ที่ API ใช้งาน — `tbl_articles` (บทความ 83 แถว), `tbl_page` (SEO 7 แถว), `tbl_promotion` (โฆษณา 4 แถว) **ยังมีข้อมูลอยู่ในฐานข้อมูลแต่ไม่มี endpoint ใช้แล้ว** ตั้งแต่ลบ `/api/admin/articles`, `/ads`, `/seo-pages` เมื่อ 10 ก.ย. 2026 (หน้าแอดมินทั้ง 3 เหลือเป็น placeholder)

### ความสัมพันธ์หลัก

```
tbl_item_type ──1:N──> tbl_item ──1:N──> tbl_attribute_value <──N:1── tbl_attribute
                          │
                          ├── itm_model_code  ─┐ เก็บเป็นข้อความคั่นจุลภาค
                          └── itm_option_code ─┘ ("MD-0000001,MD-0000002")
                                               → tbl_item_model / tbl_item_option
```

**สองเรื่องที่มักถูกถามตอนนำเสนอ:**

1. **สเปคเก็บแบบ EAV (Entity-Attribute-Value)** — ไม่ได้ทำคอลัมน์ต่อสเปค เพราะสินค้าแต่ละหมวดมีสเปคไม่เหมือนกันเลย (กล้องมี "ความละเอียด" ส่วน GPS มี "ค่าความแม่นยำ") การเพิ่มหัวข้อใหม่จึงทำได้จากหน้าแอดมินโดยไม่ต้องแก้ฐานข้อมูล — แลกกับการที่ query ซับซ้อนกว่าตารางปกติ
2. **สเปคเฉพาะโมเดล** — `tbl_attribute_value.model_code` ถ้าเป็น `NULL` แปลว่าเป็นสเปคที่ทุกโมเดลใช้ร่วมกัน ถ้าไม่ `NULL` คือค่าที่ override เฉพาะโมเดลนั้น

## 5. ฟีเจอร์เด่นและวิธีทำงาน

### 5.1 ระบบค้นหา (Fuzzy Search)

ระบบ**ไม่ได้ใช้ `LIKE '%คำค้น%'`** ซึ่งจะพลาดทันทีที่พิมพ์ผิด และ**ไม่ได้ใช้ full-text search ของ Postgres** เพราะภาษาไทยไม่มีช่องว่างระหว่างคำ ทำให้ตัดคำผิดบ่อย

ใช้ **fuse.js** ทำ approximate string matching (อัลกอริทึม Bitap) ในชั้น Node แทน โดยให้น้ำหนักต่างกันตามความสำคัญของฟิลด์:

| ฟิลด์ที่ใช้เทียบ | น้ำหนัก |
|---|---|
| ชื่อสินค้า | 0.6 |
| ชื่อหมวดหมู่ | 0.3 |
| แท็กสินค้า | 0.3 |
| ค่าสเปคสินค้า | 0.1 |

- `threshold: 0.3` — ยิ่งค่าน้อยยิ่งต้องเหมือนมาก (ปรับจากการทดสอบคำค้นจริงในระบบ)
- คะแนนที่คืนกลับหน้าเว็บคือ `relevance_score = 1 − score` (ยิ่งสูงยิ่งตรง)
- ถ้าไม่เจอเลย → เปิดโหมด **"คุณหมายถึง…?"** ด้วย threshold ที่หลวมกว่า (0.6) เสนอชื่อสินค้าใกล้เคียงสูงสุด 5 รายการ
- Autocomplete เรียกแบบ **debounce 300 ms** และมี guard "คำตอบล่าสุดชนะ" กันผลลัพธ์เก่ามาทับผลใหม่

### 5.2 ตารางเปรียบเทียบสินค้า

หัวใจของโปรเจกต์ — จุดที่ต่างจากเว็บ e-commerce ทั่วไป:

- **1 ช่องเปรียบเทียบ = คู่ (สินค้า, โมเดล)** ไม่ใช่แค่สินค้า → **เทียบสินค้าตัวเดียวกันคนละโมเดลได้** เช่น K2 Car Charger vs K2 Fuse Tap
- ผู้ใช้เลือกขนาดตารางเองได้ **2 / 3 / 4 ช่อง** (เพดานระบบ 4) เก็บใน `localStorage` พร้อมรายการสินค้า (ไม่ต้องล็อกอิน ปิดเบราว์เซอร์แล้วยังอยู่) — ย่อขนาดตอนสินค้าล้นช่องจะถามยืนยันก่อนตัดสินค้าท้ายรายการออก
- **คัดกรองด้วยฟีเจอร์** — ติ๊กสเปคที่ต้องการ ระบบนับว่าสินค้าไหนมีครบกว่า แล้วเรียงตัวที่ตรงที่สุดไว้ซ้ายสุดพร้อมป้าย **"แนะนำ"**
- **เรียงลำดับ** — สเปคที่เป็นตัวเลขจะมีปุ่มเรียงมาก→น้อย/น้อย→มาก กำกับ ส่วนสเปคที่เป็นข้อความล้วนจะไม่มีปุ่ม (ระบบไม่เดาว่าอันไหน "ดีกว่า")
- **ป้าย "เหมือนกัน / ต่างกัน"** ต่อแถว + ปุ่มซ่อนแถวที่เหมือนกันทั้งหมด
- **แชร์ลิงก์** `/compare?ids=itm-0000017:MD-0000003,itm-0000081` เปิดแล้วได้ตารางเดิม

> ระบบจะ**ไม่ขึ้นป้าย "แนะนำ"** ถ้าค่าที่เทียบกันเหมือนกันและไม่ใช่ตัวเลขที่ตัดสินได้ว่าอันไหนดีกว่า — เจตนา ไม่ใช่บั๊ก

### 5.3 โมเดลสินค้าและตัวเลือกเสริม

สองอย่างนี้ต่างกัน มักสับสน:

| | **โมเดลสินค้า** (`tbl_item_model`) | **ตัวเลือกเสริม** (`tbl_item_option`) |
|---|---|---|
| คืออะไร | รุ่นย่อยของสินค้าเดียวกัน | ของเสริมที่ซื้อเพิ่ม |
| ตัวอย่าง | K2 Car Charger / K2 Fuse Tap | SD Card 64GB, เซ็นเซอร์วัดน้ำมัน |
| มีสเปคของตัวเอง | ✅ override สเปคสินค้าแม่ได้ | ❌ |
| เข้าตารางเปรียบเทียบ | ✅ แต่ละโมเดลเป็นคอลัมน์แยกได้ | ❌ ตั้งใจไม่เอาเข้า |
| ผลต่อราคา | ราคาต่อโมเดล + ป้าย "เริ่มต้น" | เลือกแล้วบวกเข้าราคาสินค้าทันที |

ทั้งคู่เป็น **shared catalog ทั้งระบบ** — สร้างครั้งเดียวแล้วผูกกับสินค้าหลายตัวได้ผ่าน checkbox ในฟอร์มแก้ไขสินค้า

### 5.4 ความปลอดภัย

- รหัสผ่านแอดมินเก็บเป็น **bcrypt hash** ไม่เคยเก็บเป็นข้อความจริง
- ล็อกอินสำเร็จได้ **JWT อายุ 2 ชั่วโมง** (ค่าจาก `JWT_EXPIRES`) ทุก endpoint ใต้ `/api/admin/*` ต้องแนบ token
- **Rate limit** — `/api` ทั่วไป 300 ครั้ง/15 นาที, `/api/auth` เข้มกว่าที่ 10 ครั้ง/15 นาที (กันเดารหัสผ่าน)
- `helmet` ตั้ง security header, `cors` จำกัด origin
- **ลบสินค้าเป็น soft delete** (`itm_flag='0'`) ข้อมูลไม่หายจริง กู้คืนได้จากหน้าแอดมิน

## 6. เส้นทางการทำงานหลัก (Flow)

### ลูกค้าค้นหาแล้วเปรียบเทียบ

```
พิมพ์ "dtrack" ในช่องค้นหา
   └─ debounce 300ms → GET /api/search/autocomplete → dropdown คำแนะนำ
กด Enter
   └─ GET /api/search?searchword=dtrack
        ├─ ดึงสินค้าที่ active ทั้งหมด + หมวดหมู่ + แท็ก + ค่าสเปค
        ├─ fuse.js ให้คะแนนตามน้ำหนักฟิลด์ → กรองด้วย threshold
        └─ ถ้าผลลัพธ์ = 0 → คำนวณ "คุณหมายถึง…?" ส่งกลับไปด้วย
กด "เปรียบเทียบ" บนการ์ดสินค้า
   └─ Pinia store (compare.ts) เพิ่มช่อง (product_id, model_id) ลง localStorage
เข้าหน้า /compare
   └─ GET /api/products/compare?ids=… → สร้างตารางทีละคอลัมน์ตามช่องในตะกร้า
```

### แอดมินแก้ไขสินค้า

```
POST /api/auth/login → ได้ JWT เก็บใน localStorage
เปิด /admin/products/itm-0000081/edit
   └─ GET /api/admin/products/:id (แนบ Bearer token)
กรอกฟอร์ม 5 แท็บ แล้วกดบันทึก
   └─ PUT /api/admin/products/:id
        ├─ อัปเดตฟิลด์ตาม whitelist (ไม่รับ field แปลกปลอมจาก body)
        ├─ applyProductAttributes()  — เขียนสเปคใหม่ทั้งชุด
        ├─ reassignProductModels()   — ผูกโมเดลที่ติ๊กไว้
        └─ normalizeOptionIds()      — ผูกตัวเลือกเสริม
```

> ⚠️ `PUT` เป็นแบบ **full-replace** — ฟิลด์ที่ไม่ส่งมาจะถูกล้าง การแก้ข้อมูลผ่าน API ตรงๆ ต้อง GET มาก่อนเสมอแล้วส่งกลับทั้งก้อน

|---|---|---|
| **ค้นหา** | fuse.js แทน `pg_trgm` / full-text ของ Postgres | ภาษาไทยไม่มีช่องว่างระหว่างคำ ตัดคำผิดบ่อย; fuse.js ปรับน้ำหนักรายฟิลด์ได้และทดสอบซ้ำได้ง่ายกว่า |
| **โครงสร้างตาราง** | ใช้สำเนาตารางจริงของ dtcshops.com | ต่อยอดกับระบบจริงของบริษัทได้ ไม่ต้อง migrate ข้อมูลใหม่ |
| **สเปคสินค้า** | EAV (`tbl_attribute` + `tbl_attribute_value`) | สินค้าต่างหมวดมีสเปคคนละชุดกันโดยสิ้นเชิง เพิ่มหัวข้อใหม่ได้จากหน้าเว็บ |
| **ความสัมพันธ์โมเดล/ตัวเลือก** | เก็บเป็นข้อความคั่นจุลภาคบน `tbl_item` | ตามโครงสร้างจริงของ dtcshops.com ที่ไม่มี join table |
| **บอกว่าสินค้าไหนดีกว่า** | เรียงลำดับคอลัมน์ + ป้าย "แนะนำ" | เดิมใช้ไฮไลต์เขียว/แดงรายเซลล์ แต่ตัดสินไม่ได้จริงกับสเปคที่เป็นข้อความ จึงเปลี่ยนเป็นเรียงเฉพาะสเปคที่ "คำนวณได้" และไม่เดาที่เหลือ |
| **ตะกร้าเปรียบเทียบ** | `localStorage` ไม่ใช่ session ฝั่ง server | ฝั่ง public ไม่มีระบบสมาชิก ไม่ต้องล็อกอินก็ใช้ได้ |
| **i18n** | เฉพาะฝั่ง public หน้าแอดมินเป็นไทยล้วน | ผู้ใช้แอดมินคือทีมงานคนไทย ไม่คุ้มที่จะแปล 3 ภาษา |
| **รูปภาพ** | เก็บไฟล์บนดิสก์ DB เก็บแค่ path | ไม่ทำให้ DB บวมและ backup ช้า |

## 8. ข้อจำกัดที่ยอมรับแล้ว (ตอบตรงๆ ได้ถ้าถูกถาม)

1. **ไม่มีตะกร้าสั่งซื้อ/ชำระเงิน** — โดยเจตนา ระบบนี้เป็นเครื่องมือค้นหา/เปรียบเทียบ การสั่งซื้อส่งต่อไป Shopee/Lazada/TikTok/LINE
2. **ไม่มีระบบสมาชิกฝั่งลูกค้า** — มีแค่บัญชีแอดมิน
3. **เนื้อหาสินค้าเก็บภาษาเดียว** — สลับ TH/EN/JA เปลี่ยนเฉพาะข้อความของตัวเว็บ ชื่อ/รายละเอียดสินค้ายังเป็นภาษาที่แอดมินกรอกไว้ (ถ้าจะรองรับต้องเพิ่มคอลัมน์ต่อภาษาหรือตารางแปลแยก)
4. **1 สินค้าอยู่ได้หมวดเดียว** — โครงสร้างปัจจุบันเป็น `itm_type_code` เดี่ยวบน `tbl_item` (มีแนวทางขยายไว้แล้ว ดูข้อ 9)
5. **ไม่มี migration history** — ใช้ `prisma db push` ระหว่างพัฒนา `schema.prisma` กับ DB จริงมีโอกาส drift ต้องระวัง
6. **ยังไม่มี unit test / E2E test อัตโนมัติ** — ทดสอบด้วย Playwright แบบสั่งรันเองต่อรอบการแก้ไข (รวมถึงการตรวจ accessibility ด้วย axe-core ที่รันแบบสั่งเองเช่นกัน ยังไม่ผูกกับ CI)
7. ~~**หน้าเข้าสู่ระบบแอดมินยังไม่ผ่านเกณฑ์ contrast**~~ — แก้แล้ว 11 ก.ย. 2026 (ปุ่มเข้าสู่ระบบเข้มขึ้นเป็น `brand-700` + ครอบเนื้อหาด้วย `<main>`) ตอนนี้ผ่าน axe 0 ข้อผิดพลาดทุกหน้า
8. **ปุ่มสั่งซื้อใช้เฉดสีเข้มกว่าโลโก้จริงเล็กน้อย** — สีเขียว LINE/ส้ม Shopee จากโลโก้ตรงๆ ให้ค่า contrast กับตัวอักษรขาวไม่ถึงเกณฑ์ จึงใช้เฉดเข้มขึ้นของสีเดียวกันแทน

## 11. บันทึกการแก้ไขล่าสุด (9 ก.ย. 2026)

รายการที่เปลี่ยนพฤติกรรมของระบบหลังเอกสารชุดนี้ถูกเขียนครั้งแรก — บันทึกไว้กันเอกสารกับโค้ดหลุดจากกัน

| เรื่อง | เปลี่ยนอะไร |
|---|---|
| **แบ่งหน้าแล้วสินค้าซ้ำ/หาย** | `GET /api/products` และ `GET /api/search` เดิมเรียงด้วยคอลัมน์เดียวที่มีค่าซ้ำกันมาก (31/44 ตัวมี `ist_dt` เท่ากัน) พอค่าเท่ากัน Postgres ไม่รับประกันลำดับ ทำให้สินค้าโผล่ทั้งหน้า 1 และ 2 ส่วนอีก 8 ตัวหายไป — เพิ่ม `itm_code`/`product_id` เป็นตัวตัดสินลำดับสำรองปิดท้ายทุกแบบการเรียง |
| **สินค้าที่เกี่ยวข้อง** | จาก `take: 4` เป็นทั้งหมวดหมู่ (แคโรเซลเลื่อนได้จริง) |
| **รูปสินค้าถูกครอป** | การ์ดสินค้าและรูปหลักหน้ารายละเอียดเปลี่ยนจาก `aspect-square` + `object-cover` เป็น `aspect-[4/3]` + `object-contain` — รูปสินค้า 26/43 ตัวเป็นแนวนอน (กว้างถึง 2.97:1) เดิมจึงโดนตัดจนดูไม่ออกว่าคืออะไร |
| **การ์ดสูงไม่เท่ากัน** | เพิ่ม `h-full` ที่ root ของ `ProductCard.vue` — เดิมกล่องครอบในแคโรเซลยืดเต็มความสูงแถวแต่ตัวการ์ดไม่ได้ยืดตาม |

| **ข้อมูลสินค้า** | เพิ่มสเปค SWI-M 18 ค่า (สร้างหัวข้อใหม่ 3: ความชื้นสัมพัทธ์ / เสาอากาศ / ความไวสัญญาณ GPS) และเพิ่มสินค้าใหม่ `Dtrack` (`itm-0000081`, 16 สเปค) |

## 12. บันทึกการแก้ไขล่าสุด (10 ก.ย. 2026) — งานขัดเกลา Week 14–15

| เรื่อง | เปลี่ยนอะไร |
|---|---|
| **เรียงตามราคา** | สินค้าที่ยังไม่ตั้งราคา (แสดงว่า "ราคาติดต่อสอบถาม") ถูกดันไปท้ายรายการเสมอ ทั้งเรียงน้อย→มากและมาก→น้อย — ทั้งใน `GET /api/products`, `GET /api/search` และตารางเปรียบเทียบ |
| **Loading skeleton** | ทุกหน้าฝั่ง public + ตารางหน้าแอดมิน แสดงโครงร่างเทาแทนข้อความ "กำลังโหลด" (`SkeletonBox.vue` / `ProductCardSkeleton.vue` / `TableRowsSkeleton.vue`) |
| **Error boundary** | `ErrorBoundary.vue` ห่อ `<router-view>` ทั้งสอง layout — error ตอน render ไม่ทำให้หน้าขาวทั้งหน้าอีกต่อไป แสดงกล่องแจ้งเตือน + ปุ่มโหลดใหม่แทน โดยเมนู/หัวเว็บยังอยู่ครบ · มีอีกชั้นนอกสุดใน `App.vue` สำหรับกรณีตัว layout พังเองหรือหน้าล็อกอินแอดมิน |
| **Accessibility** | ตรวจด้วย axe-core จริงแล้วไล่แก้จนเหลือ 0 ข้อผิดพลาด — สี contrast, ปุ่มไอคอนที่ไม่มีชื่อ, landmark, ลำดับหัวข้อ, ป็อปอัป (`role="dialog"` + ปิดด้วย Esc), ข้อความแจ้งเตือน (`aria-live`) |
| **Input sanitization / XSS** | middleware ตัวเดียวใน `routes/admin.js` ทำความสะอาด `req.body` ทุก endpoint ที่เขียนข้อมูล — จุดสำคัญคือฟิลด์ลิงก์ที่ถูกเอาไปใส่ `:href`/`<iframe>` ตรงๆ (ค่าอย่าง `javascript:` ถูกตัดเป็น null) |
| **จำกัดค่า page/limit** | `?limit=999999` เดิมดึงทั้งตารางมาทีเดียว, `?page=abc` ทำให้ตอบ 500 — ตอนนี้ถูกบีบให้อยู่ในช่วงที่รับได้เสมอ |
| **API caching** | หมวดหมู่/footer/แบนเนอร์/สาขา แคชในหน่วยความจำ 5 นาที และล้างอัตโนมัติทุกครั้งที่แอดมินบันทึกข้อมูล (หมวดหมู่: 273 ms → 19 ms) |
| **Lazy loading รูป** | ทุก `<img>` มี `loading="lazy"`/`decoding="async"` ยกเว้นรูปครึ่งบนของจอ — ระบบย่อรูปอัตโนมัติ (`imageResize`) ที่เพิ่มในวันเดียวกันถูกถอดออกแล้ว รูปส่งเป็นไฟล์ต้นฉบับ |
| **Code splitting** | Leaflet (150 kB) ย้ายไป dynamic import — chunk ของหน้าแรกเหลือ 21.7 kB จาก 171 kB |
| **Database index** | เพิ่ม 4 index บน `tbl_item` ตามรูปแบบ query ที่ใช้จริง (รายการสินค้า / เรียงราคา / เปิดจาก slug / เช็ค SKU ซ้ำ) |
